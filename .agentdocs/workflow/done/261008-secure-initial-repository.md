# 安全初始化 Sub-Store 脚本仓库

## 背景

原始初始提交误包含 `subscribe/` 下的真实订阅配置。用户已删除 `HEAD` 引用，需要在首次重新提交前清理索引。同时，Sub-Store 生成配置仍使用 Mihomo 已移除的顶层 `global-client-fingerprint`，导致 FlClash 导入失败。

## 实施阶段

- [x] 确认旧提交引用已删除，仓库处于无提交状态。
- [x] 下载并只读检查实际生成配置，确认废弃字段和逐代理字段现状。
- [x] 添加忽略规则并从 Git 索引移除订阅文件。
- [x] 删除模板中的废弃顶层字段，新增逐代理指纹后处理脚本。
- [x] 补充版本说明、内容管理规则和自动化测试。
- [x] 完成安全扫描、语法测试和 Git 索引检查。
- [x] 创建不含敏感订阅文件的新初始提交。

## 验收结果

- Git 历史仅保留新的安全初始提交。
- `git ls-files subscribe` 无输出，`subscribe/` 本地文件仍保留。
- 所有受管理 YAML 模板不包含 `global-client-fingerprint`。
- 实际生成配置经后处理后删除顶层旧字段，并给适用代理补充 `client-fingerprint: chrome`。
- 根目录文档已说明每个现有版本及后续内容管理方法。
